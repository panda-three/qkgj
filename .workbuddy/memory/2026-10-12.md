### ★ 沙箱硬限制：禁止加载 .node 原生扩展
**现象**：`next dev` 启动瞬间 SIGBUS，日志 0 字节，进程秒退。

**逐层排查**：
| 手段 | 结果 |
| --- | --- |
| `file` 检查二进制 | 正常，魔数 `cffaedfe`（标准 Mach-O），1.8MB 完整 |
| `codesign --force --sign -` 补签名 | 失败：`main executable failed strict validation` |
| 装 `@next/swc-wasm-nodejs` WASM 版 | 加载成功但 `Reflect.get called on non-object`，与 Next 15 不兼容 |
| WASM 版本对齐到 15.5.27 | 仍报同错，WASM 实现与 Next 15 内部 API 不匹配 |
| `next build` 生产构建 | 退出码 138（SIGBUS），同样卡在 SWC |

**结论**：文件本身完全正常，是沙箱策略禁止 `dlopen` 原生扩展。无解。
**规避方式**（已实现）：`scripts/swc-shim.cjs` 用模块解析钩子把原生 SWC
重定向到 WASM 版，能让 Next 启动到 `✓ Ready`，但编译页面时仍失败。

### 重要：这是环境限制，不是代码缺陷

### 响应式断点
<768px 侧栏抽屉 / 表格转卡片 / 弹窗转底部抽屉；
768+ 侧栏常驻；1024+ 筛选三列；1280+ 筛选四列。
**表格转卡片的原因**：线索表 12 列，横向滚动会让「跟进」「转商机」永远看不到。

### 踩坑：JS 初始化顺序
`$('.hamburger').onclick = openNav` 写在顶栏渲染之前，
元素尚未创建 → `Cannot set properties of null` 白屏。
**修复**：绑定必须晚于渲染；另加 `on(sel, evt, handler)` 安全封装，
元素缺失时 console.warn 而非崩溃。

### 踩坑：file:// 下 fetch 被拦
浏览器用 file:// 打开时禁止读本地 JSON（CORS）。
**修复**：`scripts/export-preview.ts` 把数据内联为 `window.__QK_DATA__`，
JS 优先级：内联 > fetch > 提示。
导出时先正则清掉上一轮内联块，避免重复导出无限累积。
