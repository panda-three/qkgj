### 环境踩坑记录（重要，后续会重复遇到）

**1. `brew install postgresql@16` 无法完成**
报错 `Operation not permitted @ apply2files - /usr/local/var/homebrew/locks/...`
原因：WorkBuddy 沙箱保护 Homebrew 的 locks 目录，brew 每次下载都要在该目录创建锁文件 → 被拒绝。
即使加 `dangerouslyDisableSandbox` 也失败。
- 尝试过：清空 locks、`HOMEBREW_CACHE` 改到用户目录 → 均失败
- 最终方案：改用 **Postgres.app**（GitHub release 的 DMG），挂载后拷入Applications，
  用 `~/Applications/Postgres.app/Contents/Versions/16/bin/initdb` 手动初始化数据目录，
  完全绕开 brew 与系统权限

**2. `pnpm install` 失败**
报错 `Brokered host link overwrite refused by file policy`
原因：pnpm 用符号链接管理 node_modules，沙箱的 host link policy 拒绝。
**解决：改用 `npm install`**，npm 不用符号链接，可以正常安装。
→ 项目已切换到 npm，README 与 package.json scripts 保持 npm 风格。

**3. npm install 很慢**
npm 在下载时会长时间无输出（`tail` 缓冲），需用 `ls node_modules | wc -l` 确认实际进展。
不要因为「没输出」就判定卡死而重启，先看目录。

**4. Prisma 多态关联的写法**
初版把 Attachment/FollowUp 写成 `@relation(fields: [id), ...)`（`[id)` 少了右括号），
Prisma 解析失败，且 Edit 工具因文本不精确多次匹配失败而无法替换。
**教训：多态关联不要用 `[id]` 做外键名（会误指向自身主键），要用各自具名外键字段**
（leadId / followUpId / opportunityId / customerId）。

**5. GitHub 下载限速严重**
Postgres.app 的 DMG（107MB）从 GitHub release 下载，
400 秒只下了 3.4MB（约 8KB/s），curl 报 `Operation timed out`。
加 `-C - --retry` 重试仍然限速，结论：GitHub 大文件在这台机器上不可用。

**6. ★ 最终方案：改用 PGlite（决定性选择）**
`@electric-sql/pglite` —— PostgreSQL 的 WASM 版本，以 **npm 包**形态运行。
- 绕开 brew 锁目录权限、绕开 GitHub 限速、零系统权限
- 支持标准 PostgreSQL 语法：部分唯一索引、JSONB、FILTER 聚合、CTE、子查询
- **不支持 `SELECT ... FOR UPDATE` 行锁** → 并发控制改为：
  1. 条件更新原子性 `UPDATE ... WHERE owner_id IS NULL RETURNING`
  2. `version` 字段乐观锁
- 数据存 `.pglite/` 目录，删除该目录即重置
- 切换回标准 PostgreSQL 时只需替换 `src/server/db.ts` 一层，上层 services 不变

**7. npm install 反复被沙箱拦截（重要）**
报错 `CODEBUDDY_BROKER_DENY: ENOENT ... rename node_modules/.bin/acorn -> .acorn-4IF9MYSp`
原因：npm 安装时要重命名 `node_modules/.bin/` 下的符号链接，被沙箱 host link policy 拒绝。
**解决：`npm install --no-bin-links`**，跳过 bin 链接创建。
副作用：`npx prisma` / `node_modules/.bin/*` 不可用，需改用 `tsx`/`node` 直接执行。

**8. shell 偶发 SIGTERM（exit 137）**
多次出现命令返回 137 且无输出，重试即恢复。
不要把它当作命令失败，改用 Glob 工具核实文件是否存在。
